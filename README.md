# ClassTap Attendance

A focused attendance web app for one professor teaching multiple class groups. The most-used action is intentionally optimized to:

**Choose schedule/date → tap only absent students → Save Attendance.**

There is no authentication, multi-professor support, timetable automation, messaging, marks, assignments, or other modules.

## Included features

- Dynamic schedules: Year 1–4 + CSE/ECE/IT + class label + timing.
- Bulk student entry by pasting one name per line (commas also work).
- Fast card-based daily attendance: all students default to present; tapped cards are absent.
- Save and edit the same schedule/date without duplicate attendance rows.
- Per-student attendance percentage: `(days attended / total class days conducted) × 100`.
- Class summary with days conducted and class average.
- Mobile-first UI with Tinder/Instagram-inspired gradient energy, but original branding/components.
- GitHub Pages deployment workflow.
- Supabase Postgres schema and browser API access.

## Architecture

```text
GitHub Pages
  React + TypeScript + Vite frontend
          |
          | Supabase JS / autogenerated REST API
          v
Supabase Postgres
  schedules
     └── students
           └── attendance_records
```

No custom server is necessary for this scope. Supabase automatically exposes the Postgres tables through its Data API, and the frontend uses `@supabase/supabase-js` to call it.

## Database model

### schedules

- `id`
- `year` (1–4)
- `department` (CSE / ECE / IT)
- `label`
- `timing`
- `created_at`

### students

- `id`
- `schedule_id` → schedules
- `name`
- `display_order`
- `created_at`

### attendance_records

- `id`
- `schedule_id` → schedules
- `student_id` → students
- `attendance_date`
- `present` boolean
- `created_at`
- `updated_at`

A unique constraint on `(schedule_id, student_id, attendance_date)` makes daily saves idempotent: saving an existing date updates it rather than duplicating it.

The database also enforces that an attendance record's `student_id` belongs to the same `schedule_id`.

## One-time Supabase setup

1. Create a Supabase project.
2. Open **SQL Editor**.
3. Paste and run [`supabase/schema.sql`](supabase/schema.sql).
4. In Supabase **Project Settings → API**, copy:
   - Project URL
   - anon/publishable key
5. Copy `.env.example` to `.env.local` and fill the values:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

### Important security note

The requested scope explicitly excludes authentication. Because the app must still write from a browser, `schema.sql` enables public `anon` CRUD policies for these three tables. That means anyone who can reach the deployed app and knows its public Supabase configuration can access the attendance data.

For a classroom prototype or private demonstration this follows the requested scope. For real student data, adding authentication and professor-scoped Row Level Security should be the next security step.

Requires Node.js 22.12+.

```bash
npm install
npm run dev
```

Open the local URL printed by Vite.

## Deploy free-tier frontend on GitHub Pages

A workflow is already included at `.github/workflows/deploy.yml`.

1. Create a GitHub repository and push this project to the `main` branch.
2. Repository **Settings → Secrets and variables → Actions → New repository secret**.
3. Add:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. Repository **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Push to `main`, or manually run the workflow in **Actions**.

The Vite config automatically uses the repository name as the GitHub Pages base path during GitHub Actions builds.

## Attendance save behavior

For a selected schedule/date:

1. Load all students.
2. Load any existing attendance records for that date.
3. If no records exist, every student starts visually as **Present**.
4. Tapping a student toggles them to **Absent**.
5. Saving upserts one attendance row for every current student.
6. Opening the same date again loads the existing values and allows editing.

## Percentage calculation

For a schedule:

```text
total days conducted = number of distinct attendance_date values saved
student days attended = count of that student's rows where present = true
percentage = student days attended / total days conducted * 100
```

If no attendance has been conducted yet, the UI displays `—` rather than dividing by zero.

## API operations used

No custom API routes are required. The Supabase SDK maps these operations to the platform's autogenerated REST endpoints:

- `GET schedules`
- `POST schedules`
- `DELETE schedules/:id`
- `GET students?schedule_id=...`
- `POST students`
- `DELETE students/:id`
- `GET attendance_records?schedule_id=...&attendance_date=...`
- `UPSERT attendance_records` on `(schedule_id, student_id, attendance_date)`
- `GET attendance_records?schedule_id=...` for summary calculation
